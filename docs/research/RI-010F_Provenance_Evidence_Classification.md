# RI-010F — PROVENANCE AND EVIDENCE CLASSIFICATION FRAMEWORK

## 1. Executive Summary

This report systematizes, audits, and classifies all evidence rules compiled across research passes RI-010A through RI-010E (130+ rule IDs). It formalizes the criteria for separating core Parashari root-text authority from commentary-dependent variants and modern interpretations.

**Key findings:**
- **103 rules** (78%) are classified as `SOURCE-PINNED CLASSICAL` — directly traceable to BPHS, Phaladeepika, or Jataka Parijata root texts.
- **27 rules** (21%) are classified as `COMMENTARY-DEPENDENT` — primarily from Saravali, Brihat Samhita, or later commentaries.
- **0 rules** are classified as `LATER TRADITION`, `MODERN INTERPRETATION`, `PROJECT SYNTHESIS`, or `REJECTED`.
- **All 130 rules** have `PENDING PRINTED-EDITION VERIFICATION` status.

### 2.2 Classification Criteria

| Bucket | Definition | Decision Rule |
|--------|-----------|---------------|
| **SOURCE-PINNED CLASSICAL** | Directly traceable to BPHS, Phaladeepika, or Jataka Parijata with chapter/verse citation | Claim appears verbatim or paraphrased in root text; cited chapter exists in standard editions |
| **COMMENTARY-DEPENDENT** | Found in Saravali, Brihat Samhita, Uttara Kalamrita, or named commentaries | Claim appears in non-BPHS classical text; or is a commentary interpretation of root text |
| **LATER TRADITION** | Post-classical synthesis not traceable to any named text | No text citation; appears in modern compilations only |
| **MODERN INTERPRETATION** | 20th/21st century interpretive addition | Psychological or New Age additions to classical framework |
| **PROJECT SYNTHESIS** | JRS-specific combination of multiple classical rules | Engine-specific logic not found in any single text |
| **SOURCE UNVERIFIED** | Claim believed to be classical but source not yet identified | Pending research confirmation |
| **REJECTED / INSUFFICIENT EVIDENCE** | Claim contradicted by root texts or insufficient evidence | Contradicted by BPHS/Phaladeepika/Jataka Parijata |

### 3.2 Resolution Principles

When classical sources diverge, the JRS engine applies the following hierarchy:

1. **BPHS (Brihat Parashara Hora Shastra)** — Highest authority. Parashari system foundation.
2. **Phaladeepika** — Second authority. Practical application of BPHS principles.
3. **Jataka Parijata** — Third authority. Synthesis of BPHS and other texts.
4. **Saravali** — Commentary authority. Detailed explanations of root text principles.
5. **Brihat Samhita** — Supplementary authority. Specific topics (transits, eclipses).

**Conflict resolution rule:** When BPHS and Phaladeepika agree, their combined authority is definitive. When they disagree, BPHS takes precedence (as the foundational text). Phaladeepika additions are treated as "refinements" that modify implementation details but not core formation logic.

```json
{
  "rule_id": "KT-001",
  "claim": "Kendra lords + Trikona lords conjunction = Raja Yoga",
  "source_text": "BPHS",
  "chapter": "41",
  "verse_start": null,
  "verse_end": null,
  "edition_id": "Ganeshan-2019",
  "evidence_category": "SOURCE-PINNED CLASSICAL",
  "confidence_weight": 1.0,
  "printed_verification_status": "PENDING",
  "conflicting_sources": [],
  "resolution_strategy": "BPHS-primary",
```

### 5.4 Schema Validation Rules

1. `rule_id` must be globally unique across all rule sets (KT, PA, MY, TA, VG).
2. `source_text` must be one of: `BPHS`, `Phaladeepika`, `Jataka Parijata`, `Saravali`, `Brihat Samhita`, `Jaimini Sutras`, `Uttara Kalamrita`.
3. `evidence_category` must be one of the 7 project buckets.
4. `confidence_weight` must be in range [0.0, 1.0].
5. `printed_verification_status` must be one of: `PENDING`, `VERIFIED`, `MODIFIED`, `REJECTED`.
6. `conflicting_sources` must reference valid `rule_id` values.
7. Rules with `REJECTED` status must not be loaded into the engine catalog.
